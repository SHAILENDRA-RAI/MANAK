# 04 — Backend API Specification
## INVICTUS | FastAPI | Version 1

### 1. API principles
REST JSON under `/api/v1`; OpenAPI generated by FastAPI. UTC timestamps in ISO-8601. Currency is INR integer/decimal, never floating-point in persistence. Every response includes `request_id`. Validate all inputs server-side. Never trust client-supplied valuation outputs or role claims.

### 2. Authentication and authorization
Use Supabase Auth JWT or an equivalent OIDC provider. Backend verifies signature, issuer, audience, expiry, and subject. Map identity to database roles. Roles:
- `ADMIN`: users, source registry, model registry, audit and configuration.
- `VALUATION_ANALYST`: create/edit draft property inputs, run valuations, view reports and comparables.
- `LOAN_OFFICER`: view approved valuation reports and preliminary collateral metrics; cannot change model/data.
- `DEMO_VIEWER`: read-only access to seeded demo cases and demo reports.
Least privilege applies. Demo credentials must be isolated and carry no real customer data.

### 3. Endpoints
- `GET /health`: liveness; no secrets or DB details.
- `GET /ready`: dependency readiness (DB/model artifact).
- `GET /me`: current user and effective roles.
- `GET /cities`: enabled city/property scope; MVP returns Jaipur + residential apartment.
- `GET /localities?city_id=`: supported locality list.
- `POST /properties`: create property input. Returns `201` and property ID.
- `GET /properties/{property_id}`: retrieve property and provenance summary.
- `PATCH /properties/{property_id}`: update editable inputs; creates observation/audit history.
- `POST /properties/{property_id}/coverage-check`: returns data category status and missing fields; must not imply integration where absent.
- `POST /valuations`: create valuation request; accepts `property_id` or validated inline property payload, `purpose`, `include_comparables`.
- `GET /valuations/{valuation_id}`: result, confidence, factors, sources, comparables, disclaimers.
- `GET /valuations/{valuation_id}/report`: printable report payload or PDF generation endpoint.
- `GET /valuations/{valuation_id}/audit`: authorized audit trail.
- `GET /market/localities/{locality_id}`: only publish market indicators with source and date.
- `GET /models/active`: active model metadata and validation status; admin/analyst.
- `GET /models/metrics`: metrics, sample count, evaluation date, split protocol; do not expose unsupported claims.
- `POST /feedback`: structured feedback; redact free text.
- `GET /admin/sources`: source registry.
- `POST /admin/sources`: register source and permission status.
- `GET /admin/audit`: filter audit events.

### 4. Example valuation request
```json
{
  "property_id": "UUID",
  "purpose": "PRELIMINARY_COLLATERAL_ASSESSMENT",
  "include_comparables": true
}
```
Inline property payload must include locality, apartment subtype, area type + value, bedrooms where known, age/condition where known, floor/total floors where known, coordinates or a confirmed locality, and source of each user-provided fact.

### 5. Example response contract
```json
{
  "request_id": "uuid",
  "valuation_id": "uuid",
  "status": "COMPLETED",
  "scope": {"city": "Jaipur", "property_type": "RESIDENTIAL_APARTMENT"},
  "estimated_value_inr": 0,
  "valuation_range": null,
  "confidence": {
    "band": "LOW",
    "rationale": ["Insufficient verified comparable evidence"],
    "calibration_status": "NOT_CALIBRATED"
  },
  "evidence_grade": "LIMITED",
  "factors": [],
  "comparables": [],
  "data_coverage": [],
  "model": {"name": "baseline", "version": "unvalidated-demo"},
  "limitations": ["Prototype estimate; not a formal valuation certificate"]
}
```
The zero is a schema placeholder only; production response must contain a positive value or a structured `INSUFFICIENT_EVIDENCE` status. Never return a fabricated numeric prediction merely to complete the response.

### 6. Validation and errors
Use standard errors: `400 VALIDATION_ERROR`, `401 UNAUTHENTICATED`, `403 FORBIDDEN`, `404 NOT_FOUND`, `409 CONFLICT`, `422 INSUFFICIENT_EVIDENCE`, `429 RATE_LIMITED`, `500 INTERNAL_ERROR`, `503 MODEL_UNAVAILABLE`. Error body: `{request_id, code, message, field_errors?}`. Avoid leaking stack traces or provider secrets.

### 7. Valuation orchestration
1. Authenticate and authorize.
2. Validate property scope; reject unsupported cities/types with `422 SCOPE_NOT_SUPPORTED`.
3. Persist input snapshot and provenance.
4. Run data coverage and quality checks.
5. Retrieve eligible comparables; exclude synthetic and non-transaction evidence from sale-based model training.
6. Invoke active model only if model status is approved and inputs satisfy quality gates.
7. Generate calibrated uncertainty only if calibration exists; otherwise `valuation_range=null` and confidence explicitly uncalibrated.
8. Persist factors, comparables, source lineage and model version.
9. Write audit event.
10. Return disclaimer and escalation recommendation.

### 8. Operational requirements
Set request timeouts, bounded retries, rate limits, structured logs, correlation IDs, CORS allowlist, secret management, and API versioning. No API keys in browser code or Git. Do not expose raw deed/document data.
